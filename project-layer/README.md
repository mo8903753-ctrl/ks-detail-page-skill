# 启动问询协议（skill 激活后的第一动作）

原则：**你问用户，不是用户填文件。** 先读用户已丢进来的一切资料（链接/文件夹/文档），
能读出来的绝不再问；剩下的分两轮问完，每轮一次性提出，不挤牙膏。
问答结果由你写进 project.json、品类附录（仿 references/08 重写）、style-token 项目层。

## 第一轮 · 定向（开工前必问，可用选择题工具）
1. **产品与资料**：产品是什么？资料在哪（预热页链接/资料文件夹/规格文档）？
2. **参考竞品页**：有没有指定的竞品/标杆 KS 页链接？
   - 有 → 扒下来拆证明形式（每个卖点用什么形式举证），入品类附录
   - 没有 → 按品类搜同类 Top 案例，给用户 2-3 个候选拍板
3. **必须遵守的页面逻辑**：有没有硬性结构参考——品牌旧页面、指定样板、预热页卖点顺序？
   - 有 → 骨架继承该顺序（本套漏斗只做校验与补缺）
   - 没有 → 按 references/01 五卖点漏斗自排后给用户确认
4. **素材从哪来**：素材包路径（哪台机器）？可挖的品牌公开渠道（官网/YouTube/社媒/调研报告）？

## 第二轮 · 锁定（读完资料后问剩余项）
5. **锁定数字清单**：列出你从资料读到的关键数字（价格/重量/命名/参数），逐条请用户
   确认或标 [PENDING]——旧稿数字是事故源，未确认的绝不上图
6. **风格**：三风格比选照跑，还是有指定参考图/品牌 VI 直接锁风格？
7. **品类红线**：按品类生成候选问题（授权/商标/肖像权/合规声明），请用户确认边界
8. **协作与交付**：Codex 工作目录放哪？交付文件夹放哪台机器？（默认：codex/ 三件套
   复制进工作目录，tutti 拉起双端；交付=「最终成品」+「分类装配包」双文件夹）

## 问询后你要产出（用户零编辑）
- project.json（按 codex/project.json.template 填好实值）
- 品类附录（替换 references/08，含竞品证明形式拆解）
- style-token（模板法则层 + 问出来的项目层色彩字体）
- 待品牌清单 v1（从第 5/7 问的 PENDING 项生成，随项目滚动维护）
